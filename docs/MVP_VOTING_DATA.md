# MVP voting labels

`scripts/build_mvp_voting.py` imports a pinned, public transcription of Basketball-Reference MVP voting tables. The versioned import at `data/raw/mvp_voting/v1_325de65f7849/` contains the original source CSV, normalized vote labels, a source hash/retrieval manifest, and forward-only season folds. It covers 715 distinct vote recipients across 1980–81 through 2024–25. One exactly duplicated 1980–81 source vote row is removed; conflicting duplicates fail validation.

The labels contain vote points, maximum points, calculated share, rank, first-place votes, and winner. No statistical columns from the source enter the normalized labels. A vote recipient table is not a full candidate universe: players with zero votes must be generated from the project's player-season logs and assigned zero only after identity matching and coverage checks. Name/team text alone is not a safe automatic join; trades, suffixes, and same-name players require resolution to `PLAYER_ID`.

The included folds hold out each season ending 2018–2025, training only on earlier seasons. The first fold has two training seasons (2015–16 and 2016–17); later folds add one season each. This is a fold *plan*, not a trained award model or measured accuracy. For a season-end MVP model, season-end statistics may be used only in historical years strictly before the test year when learning weights. For a preseason or fixed-cutoff award forecast, every candidate feature must instead be frozen at that prediction cutoff. Final vote tallies, final ranks, and source-provided season statistics must never be predictors.

Rebuild with `.venv/Scripts/python.exe -m scripts.build_mvp_voting`; use `--source-file` for an already downloaded copy. The importer refuses to overwrite an existing version directory. The source is secondary, so independently compare notable seasons and winners with [NBA's official award releases](https://pr.nba.com/voting-results-2025-26-nba-regular-season-awards/) before using this dataset for reported model performance.

The independent 2025–26 holdout uses the [NBA's official MVP voting table](https://pr.nba.com/voting-results-2025-26-nba-regular-season-awards/), transcribed by `scripts/build_mvp_2026_votes.py` into `data/raw/mvp_voting/v2_2026_official_cb4ede55835f/`. The eight recipients and all five rank columns reconcile to 100 ballots per rank and 2,600 points. The source image hash and retrieval details are in its manifest; the image is a local ignored verification cache. `scripts/run_mvp_2026_holdout.py` joins these labels to cached 2025–26 player and team logs under `data/raw/live_preseason/v1_20260922T113549Z_c79af6/`, saves a separate versioned run, and trains each cutoff only on earlier seasons. The 2025–26 labels are never predictor features or training targets for that season's forecast.

The next experiment is implemented in `scripts/run_mvp_experiment.py`. It uses a reviewed suffix mapping in `data/raw/mvp_voting/name_aliases.csv`, checks that each vote recipient's team appears in their season logs, constructs zero-vote candidates, and saves chronological predictions, metrics, standardized coefficients, calibration bins, coverage, and hashed inputs under a new `data/processed/mvp_runs/` directory. See `docs/MODEL_CARD.md` for held-out results and limitations. Run it with `.venv/Scripts/python.exe -m scripts.run_mvp_experiment`.

The cutoff follow-up is `scripts/run_mvp_cutoff_experiment.py`. It freezes all features before March 1, records a conservative normal eligibility path for 2023–24 onward, and compares a learned winner model with a training-calibrated simple baseline. It writes a new versioned run with per-season top picks, probabilities, eligibility audit, rankings, source hashes, and coefficients. Run with `.venv/Scripts/python.exe -m scripts.run_mvp_cutoff_experiment`.

For multi-date validation, run `.venv/Scripts/python.exe -m scripts.run_mvp_multi_cutoff_experiment`. This builds separate January 1, February 1, and March 1 snapshots and forward-only folds. It writes candidate and prediction tables, coverage and season-stage counts, monthly metrics, paired season bootstrap comparisons, and a 2020–21 delayed-start sensitivity. Dates within the same season share one award outcome and must not be counted as independent tests.
